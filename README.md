# SSH Proxy для Keenetic — прототип

Приложение управляет клиентом OpenSSH из Entware и отдельной HTTPS-страницей. OpenSSH создаёт SOCKS5 только на `127.0.0.1:1080`; штатный клиент Keenetic должен подключаться к этому адресу. Доступ к интерфейсу и маршрутизация через локальный SOCKS на конкретном устройстве требуют проверки после установки.

Реализованы адрес, порт, пользователь, пароль или ключ и необязательный сертификат OpenSSH, проверка ключа сервера, запуск/остановка, статус, автоподключение и повтор при обрыве. Пароль и ключ хранятся в файле, доступном root; это не зашифрованное хранилище. Первичная настройка генерирует отдельный пароль к веб-странице, без стандартного пароля. Интерфейс использует собственный сертификат HTTPS.

`dist/keenetic-ssh-proxy-mipsel.tar.gz` — экспериментальная сборка Linux MIPSel soft-float. Она пока не запускалась на роутере. Для работы нужны пакеты `openssh-client` и `openssh-client-utils` (последний содержит `ssh-keyscan`). Исходники не используют сторонних Go-зависимостей.

Безопасный порядок внедрения после появления флешки:

1. Проверить модель, архитектуру, ядро, состояние `/opt`, файловую систему флешки и действующий конфиг, сохранить резервную копию.
2. Установить Entware согласно инструкции Keenetic и сменить предусмотренный установщиком пароль Entware.
3. Установить `openssh-client openssh-client-utils`. Проверить доступность сервера напрямую: IP сервера не должен маршрутизироваться через сам создаваемый прокси.
4. Скопировать бинарный файл и init-скрипт; ограничить права на файлы настроек. При инициализации задать конкретный LAN-IP для интерфейса и создать сертификат для этого адреса; не слушать WAN.
5. В профиле получить ключ сервера и самостоятельно сверить его SHA256-отпечаток по независимому каналу. Проверить SSH-соединение и SOCKS на локальном адресе, не переключая текущий прокси.
6. Только после проверки изменить адрес существующего подключения Keenetic на локальный SOCKS и проверить маршруты/доступ. При ошибке вернуть прежний адрес и настройки из резервной копии.

Пример инициализации **после проверки IP роутера**:

```sh
/opt/bin/keenetic-ssh-proxy --init --listen 192.168.1.1:8181
```

В примере `192.168.1.1` — адрес локального интерфейса роутера; используйте свой. Команда выводит пароль веб-интерфейса только при первом запуске. При смене LAN-IP сертификат необходимо перевыпустить. Доступ по HTTPS к самоподписанному сертификату потребует действия пользователя в браузере или установки доверенного сертификата. Файл `/opt/etc/ssh-proxy/listen` содержит проверенный адрес `IP:порт` для init-скрипта.

SSH динамический SOCKS передаёт TCP; UDP, в том числе QUIC и некоторые звонки, через него не проходит. Индикация «Подключено» означает, что процесс SSH запустил локальный SOCKS, а не успешную работу конкретных сайтов.
