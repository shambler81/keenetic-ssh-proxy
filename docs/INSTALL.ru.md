# Установка SSH Proxy на Keenetic

Инструкция описывает настройку, которую выполняли на **Keenetic Hero 4G KN-2310, KeeneticOS 5.1.8**, с USB-флешкой и сервером Ubuntu. На другом роутере названия пунктов меню и поддерживаемая архитектура могут отличаться. Не копируйте без проверки адреса, имена пользователей и команды форматирования для чужого оборудования.

Готовая сборка в репозитории рассчитана на **Linux MIPSel soft-float**. Приложение и панель на указанном роутере запускались, пользователь сообщил об успешной работе подключения. Этот проект пока не проверен на всех моделях Keenetic; приведённые примеры подключения другого сервера и настройки маршрутов нужно проверить на конкретной сети.

## Что понадобится

- Keenetic с USB-портом, доступом в интернет, компонентами OPKG, файловой системой Ext, SSH-сервером и клиентом прокси.
- Флешка: её содержимое будет удалено при форматировании. Оставьте её подключённой — приложения и настройки Entware находятся на ней.
- Доступ администратора к роутеру и к отдельному SSH-серверу. Сервер должен разрешать TCP port forwarding; маршруты и адрес сервера подбираются для своей сети.
- Доступ к панели с устройства в локальной сети роутера. Веб-панель приложения использует HTTPS с самоподписанным сертификатом.

Сохраните резервную копию конфигурации Keenetic через **Управление → Настройки системы → Файлы → startup-config**. Она может содержать пароли и ключи; храните её локально и не публикуйте. Если на роутере уже есть Entware, `/opt`, правила или приложения, сначала проверьте их: инструкция ниже для новой установки, а не для перезаписи существующей.

## 1. Подготовьте флешку

В KeeneticOS 5.1 форматирование доступно на странице **Управление → Накопители и устройства**. Если EXT4 отсутствует в списке форматов, откройте **Управление → Настройки системы → Изменить набор компонентов** и установите **Файловая система Ext** и **Утилиты для файловой системы Ext**. Там же проверьте **Поддержка открытых пакетов (OPKG)**, **SSH-сервер** и **Клиент прокси**. Применение компонентов может перезагрузить роутер.

Подключите флешку, проверьте её модель и объём и отформатируйте нужный раздел в **EXT4**. При использовании операции **«Инициализировать»** Keenetic может создать два раздела: EXT4 и SWAP; это нормальное поведение. Не выбирайте SWAP для установки Entware. На других версиях ОС флешку можно подготовить на компьютере. Все данные на форматируемом разделе или инициализируемом устройстве удаляются.

Источники: [форматирование накопителя на KN-2310](https://support.keenetic.com/hero-4g/kn-2310/en/100924-formatting-and-checking-a-file-system-on-a-usb-drive.html), [установка Entware на KN-2310](https://support.keenetic.com/hero-4g/kn-2310/en/20980-installing-the-entware-repository-on-a-usb-drive.html).

## 2. Установите Entware

Для **KN-2310** в официальной инструкции указан архив [EN_mipsel-installer.tar.gz](https://bin.entware.net/mipselsf-k3.4/installer/EN_mipsel-installer.tar.gz). Для другой модели сначала найдите её инструкцию Keenetic и выберите нужную архитектуру.

1. В файловом менеджере Keenetic откройте EXT4-раздел флешки, создайте в корне папку `install` и загрузите туда архив Entware **без распаковки**.
2. Откройте **Управление → OPKG**, выберите этот EXT4-раздел и сохраните. Поле сценария оставьте по умолчанию; установщик может настроить его сам.
3. В **Управление → Диагностика → Системный журнал** дождитесь сообщения о завершении Entware, например `[5/5] "Entware" installed!`. Сообщение «Настройки сохранены» ещё не означает завершение установки.

В нашем случае установщик отдельно запустил сервер Dropbear с заводским паролем Entware. Смените этот пароль после установки согласно [инструкции Keenetic](https://support.keenetic.com/hero-4g/kn-2310/en/20980-installing-the-entware-repository-on-a-usb-drive.html); пароль Entware и пароль администратора Keenetic — разные вещи. Не публикуйте журнал, конфигурацию или вводимые пароли.

## 3. Войдите в оболочку и установите пакеты

На Windows откройте PowerShell и подключитесь **к своему адресу роутера** как администратор Keenetic, например:

```powershell
ssh admin@192.168.1.1
```

Если увидели `(config)>`, это CLI Keenetic. Для перехода в Linux-оболочку выполните:

```text
exec sh
```

Должно появиться приглашение вида `/ #`. Проверьте подключённый `/opt` и архитектуры Entware:

```sh
id
ls -ld /opt
uname -m -r
opkg print-architecture
```

`id` должен показать `uid=0(root)`, а в поддерживаемых архитектурах должен быть `mipsel-3.4`. Значение `mips` из `uname -m` само по себе не определяет порядок байтов. Если `/opt` не смонтирован, архитектура не MIPSel или уже используется другая установка, остановитесь и проверьте модель и настройки.

Установите пакеты:

```sh
opkg update
opkg install openssh-client openssh-client-utils wget-ssl ca-bundle curl
```

Проверьте OpenSSH:

```sh
/opt/bin/ssh -V
ls -l /opt/bin/ssh-keyscan
```

Встроенный BusyBox `wget` на нашем роутере не поддерживал HTTPS и выдавал `not an http or ftp url`. После установки `wget-ssl` используйте полный путь **`/opt/bin/wget`**; проверку TLS отключать не нужно. `bash` не обязательно установлен: в этой инструкции используется BusyBox `sh`.

## 4. Подготовьте SSH-сервер

На своём сервере создайте **отдельного пользователя**, а не используйте root для постоянного туннеля. Один из вариантов для Ubuntu, в отдельной административной SSH-сессии:

```sh
sudo adduser --disabled-password --gecos '' keenetic-tunnel
sudo passwd keenetic-tunnel
```

Команда `passwd` попросит новый длинный случайный пароль. Не вставляйте его в команды, репозиторий или публичные журналы. Проверьте, что на сервере разрешены вход и локальное TCP forwarding:

```sh
sudo sshd -T -C user=keenetic-tunnel,host=localhost,addr=127.0.0.1 | grep -E '^(authenticationmethods|passwordauthentication|allowtcpforwarding|permitopen|forcecommand|permittty) '
```

### Ограничение пользователя сервером

Для нашей настройки использовали отдельный `Match User`: парольная аутентификация и **локальное** TCP forwarding разрешены, команды, терминал, агент и X11 запрещены. Перед изменениями сохраните серверную конфигурацию, проверьте действующие `Match`, `AllowUsers`, `DenyUsers` и порядок `Include`. Не закрывайте рабочую административную сессию до проверки. Пример содержимого нового файла `/etc/ssh/sshd_config.d/99-keenetic-tunnel.conf` для Ubuntu:

```text
Match User keenetic-tunnel
    AuthenticationMethods password
    PasswordAuthentication yes
    KbdInteractiveAuthentication no
    PubkeyAuthentication no
    AllowTcpForwarding local
    AllowAgentForwarding no
    X11Forwarding no
    PermitTTY no
    PermitTunnel no
    PermitUserRC no
    ForceCommand /bin/false
Match all
```

Перед применением проверьте конфигурацию и эффективные параметры **и нового пользователя, и администратора**:

```sh
sudo sshd -t
sudo sshd -T -C user=keenetic-tunnel,host=localhost,addr=127.0.0.1 | grep -E '^(authenticationmethods|passwordauthentication|allowtcpforwarding|permitopen|forcecommand|permittty) '
sudo sshd -T -C user=root,host=localhost,addr=127.0.0.1 | grep -E '^(authenticationmethods|passwordauthentication|allowtcpforwarding|forcecommand|permittty) '
```

Только если синтаксис корректен и действующий доступ администратора не изменился, примените настройки командой `sudo systemctl reload ssh` (имя службы может отличаться). При ошибке верните сохранённую конфигурацию и повторно выполните `sshd -t`. Для рабочего SSH-туннеля должен быть разрешён `AllowTcpForwarding local` или `yes`; `ForceCommand` ограничивает запуск команд, но соединение `ssh -N` с пробросом порта допускается. Учтите: если `PermitOpen any`, такой пользователь может через forwarding обращаться и к сетевым сервисам, доступным серверу, включая локальные; при необходимости ограничьте доступ на сервере.

На сервере получите отпечаток открытого ключа SSH-сервера и передайте его администратору роутера по доверенному каналу:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Для каждого роутера предпочтительно создавать отдельного пользователя и пароль. Приложение также поддерживает ключ OpenSSH; закрытый ключ не публикуют и не передают через публичные ресурсы. Документация: [OpenSSH sshd_config](https://man.openbsd.org/sshd_config).

## 5. Скачайте и проверьте приложение на роутере

В оболочке роутера загрузите проверенную сборку в отдельную временную папку на флешке (`/opt/tmp`). Не помещайте её в `/opt/install`: этот каталог используется установщиком OPKG.

```sh
mkdir -p /opt/tmp/ssh-proxy-setup
/opt/bin/wget -O /opt/tmp/ssh-proxy-setup/keenetic-ssh-proxy.tar.gz https://raw.githubusercontent.com/shambler81/keenetic-ssh-proxy/7b8bdd29fc7288732748836c4aab4e327560bc83/dist/keenetic-ssh-proxy-mipsel.tar.gz
sha256sum /opt/tmp/ssh-proxy-setup/keenetic-ssh-proxy.tar.gz
```

Для этого конкретного архива SHA-256 должен быть:

```text
93bc9a36868191ea7c218db26d0f173a98f2cd6b03183b8e1459441fa57de9d7
```

Если загрузка или проверка не удалась, не запускайте архив. Ссылка закреплена за конкретным коммитом; для другой версии сумма может отличаться.

```sh
cd /opt/tmp/ssh-proxy-setup
tar -xzf keenetic-ssh-proxy.tar.gz
chmod 700 keenetic-ssh-proxy
./keenetic-ssh-proxy -h
```

Ожидается справка приложения. Ошибки `Exec format error` или `not found` при наличии файла могут означать неподходящую архитектуру; проверьте её до продолжения.

## 6. Установите приложение и запустите панель

Ниже пример использует **192.168.1.1**. Замените его на проверенный **локальный адрес своего Keenetic**. Не используйте `0.0.0.0`: панель должна слушать локальный интерфейс, а не все интерфейсы. Перед установкой проверьте адрес, свободный порт и отсутствие файлов предыдущей установки:

```sh
ip -4 addr
netstat -lnt | grep ':8181 '
ls -ld /opt/bin/keenetic-ssh-proxy /opt/etc/init.d/S99sshproxy /opt/etc/ssh-proxy 2>/dev/null
```

Если приложение уже установлено или порт занят, не перезаписывайте существующие файлы: сначала выясните их назначение и сделайте резервную копию. Для новой установки:

```sh
cp /opt/tmp/ssh-proxy-setup/keenetic-ssh-proxy /opt/bin/keenetic-ssh-proxy
chmod 700 /opt/bin/keenetic-ssh-proxy
cp /opt/tmp/ssh-proxy-setup/S99sshproxy /opt/etc/init.d/S99sshproxy
chmod 700 /opt/etc/init.d/S99sshproxy
mkdir -p /opt/etc/ssh-proxy
chmod 700 /opt/etc/ssh-proxy
printf '192.168.1.1:8181\n' > /opt/etc/ssh-proxy/listen
```

В следующей команде также укажите тот же LAN-адрес. Первый запуск создаёт собственный сертификат и выводит логин `admin` и случайный пароль панели:

```sh
/opt/bin/keenetic-ssh-proxy --init --listen 192.168.1.1:8181
```

Сохраните пароль в надёжном месте. **Не публикуйте вывод команды**, файлы `web-password`, `web.key`, `config.json` и резервные копии: они содержат данные для входа и/или SSH-секреты. Если сертификат уже существует, `--init` его не перевыпускает; при смене IP необходимо отдельно перевыпустить сертификат и перезапустить панель.

```sh
/opt/etc/init.d/S99sshproxy start
/opt/etc/init.d/S99sshproxy status
netstat -lnt | grep ':8181 '
```

С устройства в локальной сети откройте `https://192.168.1.1:8181/`, заменив адрес на свой. Браузер предупредит о самоподписанном сертификате. Не открывайте панель и SOCKS в интернет. Отдельный `:8181` — адрес панели приложения; вход в штатную админку Keenetic и вход в панель приложения независимы.

## 7. Настройте SSH-профиль в приложении

Укажите свой адрес SSH-сервера, порт, отдельного пользователя и метод входа. Для проверки сервера нажмите **«Получить ключи сервера»**, выберите нужный ключ и сравните его SHA256 с отпечатком, полученным непосредственно на сервере по доверенному каналу. Введите проверенный отпечаток. Не считайте отпечаток, полученный только по проверяемой сети, независимым подтверждением.

Задайте SOCKS-порт `1080`, включите переподключение, сохраните профиль и нажмите **«Подключить»**. Если меняете настройки работающего профиля, сначала отключите его. «Подключено» означает, что SSH открыл локальный порт; интернет через него проверяется отдельно.

После успешной проверки включите **«Подключаться после запуска роутера»** и сохраните профиль; для сохранения может потребоваться сначала отключить соединение. Переподключите его и проверьте работу после перезапуска. Сам веб-сервис запускается скриптом Entware `S99sshproxy`; галочка автозапуска управляет SSH-туннелем, а не установкой службы.

## 8. Проверьте туннель до переключения Keenetic

На роутере посмотрите, каким маршрутом достигается SSH-сервер. Подставьте **свой** адрес:

```sh
ip route get <IP_SSH_СЕРВЕРА>
```

Адрес сервера должен оставаться достижимым напрямую через обычное интернет-подключение, а не через создаваемый SSH-прокси, иначе получится замкнутый маршрут. Учитывайте также политики и динамические маршруты; одной команды может быть недостаточно для полной проверки.

При работающем туннеле проверьте SOCKS локально:

```sh
/opt/bin/curl --noproxy '' --socks5-hostname 127.0.0.1:1080 --connect-timeout 10 --max-time 20 -fsS https://api.ipify.org
```

Должен показаться внешний IP выхода SSH-сервера; за NAT он может отличаться от адреса, к которому выполняется SSH. Эта проверка не гарантирует работу каждого сайта или видеопотока.

## 9. Подключите штатный прокси и настройте маршруты

В Keenetic откройте **Интернет → Другие подключения → Прокси-подключения**, создайте подключение типа **SOCKS5** к `127.0.0.1`, порт `1080`. Для нашей схемы авторизация самого SOCKS не нужна: он доступен только на loopback. Штатный клиент прокси — это отдельный интерфейс Keenetic; выключение его переключателя не останавливает процесс SSH в приложении. [Справка Keenetic о Proxy client](https://support.keenetic.com/hero/kn-1012/en/49443-proxy-client.html).

Если уже есть рабочий Proxy, политики или маршруты, экспортируйте конфигурацию и зафиксируйте настройки **до изменения**. Замена интерфейса может потребовать переназначить привязанные правила; изменение адреса существующего интерфейса также может временно прервать доступ. Не удаляйте старые маршруты без решения владельца. Для безопасного перехода сначала проверьте новый туннель, затем согласованно переключайте нужное подключение и сохраняйте возможность вернуть прежний адрес.

Для выбранных сайтов в KeeneticOS 5.x можно использовать **Сетевые правила → Маршрутизация → Маршруты DNS**: создать список доменов и правило на интерфейс прокси. Указанные домены включают поддомены; устройствам нужен DNS роутера. Собственный DoH в браузере и DNS-кэш могут мешать применению правил. Используйте DoT/DoH на самом роутере; проверьте настройки DNS с учётом своей сети. Некоторые приложения используют прямые IP-адреса, поэтому одних доменов может быть недостаточно. Диапазоны сервисов и CDN меняются, а общие IP могут использоваться несколькими сервисами — не обещайте строгого разделения по неподтверждённым спискам. [Справка Keenetic о DNS-маршрутах](https://support.keenetic.com/titan/kn-1812/en/51150-dns-based-routes.html).

Выполненный пример для YouTube, Telegram и ChatGPT и пошаговое создание правил: **[Маршрутизация выбранных сервисов](ROUTING.ru.md)**.

Проверяйте на устройстве **без ручного прокси в браузере**: выбранные сайты, обычные сайты, перезапуск приложения, доступность сервера и восстановление соединения. Если используете эксклюзивный маршрут, при недоступности прокси соответствующие адреса могут стать недоступны до его восстановления. По умолчанию старые маршруты могут направлять через прокси и другие сервисы.

## Управление и типичные проблемы

```sh
/opt/etc/init.d/S99sshproxy status
/opt/etc/init.d/S99sshproxy stop
/opt/etc/init.d/S99sshproxy start
```

Для ручного перезапуска дождитесь завершения службы между `stop` и `start`; при ошибке занятого порта проверьте процесс и журнал `/opt/var/log/keenetic-ssh-proxy.log`. Не размещайте журнал в открытом доступе без проверки.

- **`(config)>` вместо `/ #`**: вы в CLI Keenetic; выполните `exec sh`.
- **`bash executable not found`**: используйте `exec sh`.
- **`wget: not an http or ftp url` для HTTPS**: установите `wget-ssl` и `ca-bundle`, вызывайте `/opt/bin/wget`.
- **Панель не открывается**: проверьте статус, правильный LAN-IP и порт, сеть клиента и наличие флешки. Сертификат самоподписанный; KeenDNS в облачном режиме не обязательно предоставляет доступ к произвольному порту приложения.
- **SSH подключается, сайты не открываются**: проверьте прямой маршрут до SSH-сервера, forwarding на сервере, локальный SOCKS через `curl`, затем интерфейс прокси, DNS и маршруты Keenetic.
- **После перезапуска нет туннеля**: проверьте флешку, OPKG, службу и галочку автоподключения в профиле. Временное отключение службы не является удалением.
